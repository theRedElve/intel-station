# 个人情报站 · 使用说明

一个跑在本机的个人信息情报系统：自动订阅 RSS 源 → 抓取入库并去重 → 用大模型做摘要/要点/标签/重要度打分 → 按信源等级加权并对引用数据的内容提示回源核对 → 在网页仪表盘里阅读管理。

零第三方依赖，只需 Python 3.9+；数据保存在本地 SQLite，只有调用模型时联网。

---

## 一、它解决什么问题

信息分散在几十个网站和公众号里，人工刷容易漏、容易重复、也没法沉淀。情报站把这些动作自动化：

- **自动采集**：定时抓取你订阅的 RSS 源，新文章自动入库。
- **自动去重**：同一链接、转载改标题的文章只留一条，不重复占屏。
- **自动提炼**：交给大模型输出一句话摘要、关键要点、标签、涉及公司/产品，并按你的关注主题打 0–100 重要度。
- **信源分级**：给每个订阅源标记 官方 / 行业 / 媒体，加工时按等级加权，让重要度更贴近信息本身的可靠度。
- **回源提醒**：摘要或正文出现「数据显示 / 报告指出 / 研究显示 / 据统计」等表述时自动打标，日报汇总「待回源核对」。
- **留痕可检索**：全部情报存本地 SQLite，可全文搜索、按来源/主题/时间筛选，可标记已读与收藏。
- **人工评判**：每条情报可打「低 / 中 / 高」，直接校正重要度（高 +12、低 −25，可随时改回）；不需要的情报可一键丢弃（直接删除）。
- **知识库**：标记已读的情报自动沉淀成知识库，按主题、人工评判和信源等级统计，随时回看最近读过的内容。

## 二、工作原理

```
RSS 源  →  采集(抓取/正文提取/去重)  →  加工(大模型摘要·标签·打分)  →  SQLite  →  Web 仪表盘
```

1. **采集**：读取每个订阅源的 RSS/Atom（也支持 JSON 列表接口），规范化链接（去掉 utm 等跟踪参数）生成去重指纹；标题相似度超过 0.82 的视为同一条。
2. **加工**：把待处理文章按批（默认每批 6 篇）发给 OpenAI 兼容接口的模型，要求返回结构化 JSON：`summary / key_points / tags / entities / importance / reason`。未配置 API Key 或调用失败时，自动降级为规则打分（关键词命中、时效性、标题信号词），保证流程不断。加工时会读取订阅源等级（官方 +8 / 行业 +4 / 媒体 0）校正重要度，并识别引用数据的表述写入回源标记。
3. **存储**：写入本地 SQLite，记录来源、发布时间、原文正文、加工结果、已读/收藏状态。
4. **简报**：每天到点自动汇总当日高价值情报，生成 Markdown 简报刊入库中。

## 三、快速开始

| 步骤 | 操作 |
| --- | --- |
| 1 | 确认本机已安装 Python 3.9+（本项目只用标准库，无需 `pip install`） |
| 2 | 双击项目目录下的 `start.bat`，或在项目目录执行 `python app.py` |
| 3 | 浏览器打开 `http://127.0.0.1:8765`（端口被占用时会自动顺延并打印实际地址） |
| 4 | 首次启动会自动创建数据库、写入 7 个默认源并立即采集一轮 |
| 5 | 进入「设置与推送」，填入模型 API Key，点「测试连接」 |

关闭：在运行窗口按 `Ctrl+C`，或直接关闭窗口。

## 四、七个页面怎么用

### 1. 总览
- 顶部六个指标：情报总数、今日新增、未读、高价值（≥70）、待加工、订阅源数量。
- 近 7 天入库趋势、标签云、高价值情报榜、按来源的产出分布、运行日志。
- 顶部右侧：「立即采集」触发一轮抓取；「加工队列 N」把未加工文章送去分析。

### 2. 情报流
- 卡片列表展示：标题、来源与等级徽章、时间、重要度色条（红=关键 / 橙=高 / 灰=常规）、摘要、标签；引用数据的条目会标「建议回源核对」。
- 顶部筛选：搜索框、来源下拉、主题下拉、状态（全部/未读/已读/高价值/收藏）、排序。
- 卡片操作：★ 收藏、✓ 标记已读（标记后从未读移入「已读」列表）、低/中/高人工评判、✕ 丢弃（直接删除该条）。
- 点击卡片打开详情弹窗：摘要、要点、实体、标签、原文链接与回源提示；同样可收藏、标记已读、人工评判、丢弃，并对「下一条」连续阅读。
- 「加载更多」分页；搜索框支持标题、摘要、正文全文匹配。

### 3. 每日简报
- 左上角日期选择器可切换查看/生成任意一天的简报。
- 「生成简报」：汇总当日高价值情报，形成「今日综述 + 关键情报 + 待回源核对 + 主题动态」的 Markdown 简报并入库。
- 「复制 Markdown」：粘到飞书文档、笔记或邮件里。
- 简报每天在设定时间（默认 09:00）自动生成一次。

### 4. 信息源
- 已订阅源列表：名称、分类、等级（官方/行业/媒体）、状态（成功/失败）、最近抓取时间、条数；可单源「立即抓取」、编辑、删除、启用/停用。
- 新增源：粘贴 RSS/Atom 地址即可（站点只有 JSON 列表接口时也能直接填，系统自动识别），名称留空会自动识别，保存时会先校验能否解析；等级可选官方/行业/媒体，添加后也能在列表里直接改。
- 单个源抓取失败会标红并显示原因，不影响其他源。

### 5. 资源库
- 内置 40 个电商常用权威站点，按 政策与监管 / 数据与统计 / 行业研究 / 平台规则 / 学术与论文 / 资本与财报 分类。
- 顶部说明信源分级规则：官方 +8、行业 +4、媒体 0，影响之后加工的情报。
- 每个站点可「打开站点」核对原文，或「尝试订阅」——站点提供 RSS/JSON 时自动加入信息源，不提供时会明确提示。
- 可自行添加站点并标注类别、等级和备注；完整清单与核验记录见 `权威信息源清单.md`。

### 6. 关注主题
- 主题 = 名称 + 关键词（逗号分隔），用于给情报分类打分，比如「AI 与大模型：大模型,Agent,算力,推理」。
- 默认内置：AI 与大模型 / 芯片与硬件 / 创业与融资 / 产品与设计 / 开源与技术。
- 关键词命中越多、权重越高，模型打分时的主题相关分越高；规则模式同样生效。

### 7. 知识库
- 入口在左侧导航「知识库」，只统计**已读**情报：标记已读即沉淀入库。
- 顶部四个指标：已读沉淀条数、其中收藏数、已读平均重要度、已评判条数（低/中/高分布）。
- 「已读主题分布」按主题统计条数与占比；「评判与信源构成」展示人工评判分布与官方/行业/媒体来源构成。
- 「最近沉淀」按抓取时间倒序列出最近 12 条已读情报，点开可直接看详情；右上角「查看全部已读」跳转到情报流的已读筛选。

### 8. 设置
- **模型**：开关、Base URL（默认火山方舟 `https://ark.cn-beijing.volces.com/api/v3`）、API Key、模型名（默认 `doubao-seed-1-6-250615`）、批量大小。兼容 DeepSeek / 通义 / Kimi 等 OpenAI 协议服务，改 Base URL 与模型名即可。Key 保存后仅显示「已配置」，不回显明文。
- **调度**：采集间隔（默认 30 分钟）、每轮加工上限（40 篇）、每日简报时间、是否自动加工。
- **测试**：模型「测试连接」，失败会给出具体错误。

## 五、典型日常流程

1. **早上**：打开仪表盘看「总览」，扫一眼高价值榜，再看自动生成的当日简报。
2. **处理待加工**：看到「加工队列」有数字，点它（或等自动加工），几十秒后新文章都有摘要与分数。
3. **精读**：进「情报流」，按「未读 + 高价值」筛选，逐条点开看要点，重要的加收藏。
4. **补充来源**：先到「资源库」找权威站点，能订阅的一键接入、不能订阅的作为人工核对入口；读到好站点再把 RSS 加进「信息源」；关注方向变了，去「关注主题」改关键词。
5. **调优**：如果高价值内容太多，把「高价值」定义的关键词收窄；如果漏掉重要内容，检查主题关键词是否覆盖到。

## 六、配置项速查（`data/config.json`）

| 分组 | 键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| server | host / port | 127.0.0.1 / 8765 | 服务监听地址，被占用时自动 +1 顺延 |
| ai | enabled | true | 关闭后全部走规则打分 |
| ai | base_url / model / api_key | 火山方舟 / doubao-seed-1-6 / 空 | OpenAI 兼容接口 |
| ai | batch_size / timeout | 6 / 90 | 每批篇数、单次请求超时秒数 |
| schedule | fetch_minutes | 30 | 采集间隔（分钟） |
| schedule | auto_process / process_limit | true / 40 | 采集后自动加工及每轮上限 |
| schedule | digest_time | 09:00 | 每日简报生成时间 |
| collect | max_items_per_feed / keep_days | 30 / 0 | 单源每轮最多条数、保留天数（0=永久） |

配置文件也可直接编辑，改完重启生效；网页「保存设置」等价于写这个文件。

## 七、常见问题

**Q：没有 API Key 能用吗？**
能。采集、去重、搜索、简报都正常，只是摘要与打分由规则生成，精度低于模型。

**Q：某个源一直抓取失败？**
多为网络不可达、源已停更或返回非 RSS 内容。把地址在浏览器打开确认；失败的源不影响其他源，可先停用。

**Q：为什么高价值数量很少？**
重要度由主题命中、时效性、标题信号词综合计算，阈值 70 才算高价值。想放宽就在「关注主题」里补齐关键词。

**Q：「建议回源核对」是什么意思？**
说明摘要或正文出现了「数据显示 / 报告指出 / 研究显示 / 据统计」这类引用。它不代表内容有错，只提醒你在引用数字前回到政策原文、统计口径、财报或论文核对。

**Q：改了信源等级，旧情报会重新打分吗？**
不会。等级只影响之后加工的新条目；已加工的条目保留当时的重要度与打分理由。

**Q：端口 8765 被占用？**
启动时会自动尝试 8766、8767…… 实际地址看启动窗口打印的 URL。

**Q：数据在哪？怎么备份？**
`data/intel.db`（SQLite）+ `data/config.json`。复制这两个文件即完成备份，换机时放回同路径即可。

**Q：能远程访问吗？**
默认只监听 127.0.0.1（仅本机）。如需局域网访问，把 `server.host` 改为 `0.0.0.0` 并放行防火墙端口，注意接口无鉴权，不要在公网暴露。

## 八、项目结构

```
intel-station/
├── app.py          HTTP 服务、API 路由、定时调度
├── pipeline.py     采集 / 加工 / 简报流水线
├── ai.py           OpenAI 兼容模型调用、规则降级打分
├── feeds.py        RSS/Atom/RDF 与 JSON 接口解析、正文清洗、去重指纹
├── db.py           SQLite 建表、查询、统计
├── config.py       配置读写（data/config.json）

```
